SuppClaimCheck's page reader

When someone checking a supplement claim gives SuppClaimCheck the address of a web page, this reader fetches that one page, finds the claims it makes about supplements, and lets the person check one against open-access research.

What it does, and doesn't

  • It reads only the page a person asked for, once, when they ask. It doesn't crawl, follow links, index pages or come back later.
  • It reads the page as a visitor without an account would: no sign-in, no cookies, no JavaScript. Only web pages: PDFs and other files are left alone.
  • It reads robots.txt first and obeys it, and it leaves a page alone that says noai.
  • It waits at least {{ reader.min_interval_s }} second{{ "" if reader.min_interval_s == 1 else "s" }} between requests to the same site, and gives up on a page after {{ reader.timeout_s }} seconds or {{ reader.max_mb }} MB.
  • The text it reads goes to a language model only to find the claims, and is deleted with the check (privacy).

How to keep it away from your site

It identifies itself with this user agent:

{{ reader.user_agent }}

Its name in robots.txt is {{ reader.token }}, and it follows the rules for * when you don't name it. To keep it away from the whole site:

User-agent: {{ reader.token }}
Disallow: /

Or send X-Robots-Tag: noai, or put <meta name="robots" content="noai"> in a page. The reader keeps a site's robots.txt for up to {{ reader.robots_cache_minutes }} minutes, so a change applies within that time.
