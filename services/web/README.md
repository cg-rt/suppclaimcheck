# web

Public site, admin and login (D-011). Owns the `auth` schema; runs as database role `scc_web_app`. Server-rendered with Jinja2; htmx and its SSE extension (vendored in `static/js`) only for live progress.

- **Run:** `python -m scc_web` (port 8000). Migrate step: `python -m scc_web.migrate`.
- **Pages:** `/sign-in`, `/checks/new` (text, or `?from=link` for a link to a page when core's `GET /inputs` allows it, P3.12), `/checks/{id}` (confirm, progress, result or stopped, by the job's state), `/checks/{id}/events` (server-sent events), `/history`, `/account`. Ops: `/health`, `/health/deps`, `/version`.
- **Privacy and feedback** (P3.06, P4.03, D-054): `/privacy` is public and states the retention periods from `web-v1` `[privacy]`; `POST /account/delete` deletes the signed-in account and its checks (`erasure.py`: disable, ask core to erase, delete the row); a form under each result posts to `/checks/{id}/feedback`. An hourly purge inside the process deletes old sign-in attempts and ended sessions and finishes any deletion a module missed. `SCC_OPERATOR_NAME` names the controller on the privacy page. `/reader` (public) says what the page reader does and how a site keeps it away; its numbers restate gateway-v3 `[pages]`, and a test keeps them equal.
- **Admin** (P3.08-P3.10, D-049): `/admin` and its pages (jobs and traces, safety reviews, injection events, outcomes, errors, costs, evals, config, users, health) answer only on `SCC_ADMIN_HOST`, to the admin role, and behind the tunnel only with Cloudflare Access's token header; anywhere else they are a 404. Core and gateway data come from their read-only `/admin/...` endpoints (`admin_client.py`). In dev: http://admin.localhost:18080/admin with an admin account. Without the dev stack, `uv run python tools/admin_preview.py` serves admin with sample data from the test database (the canned claim run through the real pipeline, jobs in every status) at http://admin.localhost:18095/admin.
- **Accounts:** invite-only, created on the admin users page or with the admin CLI inside the container: `python -m scc_web.admin create-user someone@example.com [--admin]`, `set-password`, `disable`, and `ensure-user` (used by `deploy.sh` for the smoke account). The password is asked for at a hidden prompt, or read from stdin. In dev, `uv run python tools/dev_user.py` creates `tester@example.com`.
- **Config:** `SCC_DB_*` (see `scc_common.db`), `SCC_CORE_URL`, `SCC_GATEWAY_URL` and `SCC_ADMIN_HOST` (admin; without the host, admin is off), `SCC_TRUST_CLOUDFLARE=1` behind the tunnel (the sign-in rate limit then uses `CF-Connecting-IP`). Session, lockout, password and progress settings are versioned in `src/scc_web/config/web-v0.toml`, registered in the database by the migrate step; web reads the active version at start-up, and `python -m scc_web.config` manages versions (D-048, RUNBOOK RB-15).
- **Design:** tokens and rules in [`docs/DESIGN.md`](../../docs/DESIGN.md); stylesheet `static/css/app.css`; fonts self-hosted under the SIL Open Font License.
- **Smoke test:** `python -m scc_web.smoke [--claim]`, run after every deploy by `deploy.sh` as the `smoke` service in `compose.prod.yaml` (health, version, sign-in, history, optionally one canned claim).
- **Tests:** `uv run pytest services/web` (no database), `tests/integration/test_web_auth.py` (sign-in, lockout, sessions, CSRF, ownership; needs the test database), `tests/integration/test_admin_pages.py` (admin end to end with core and the gateway in-process), `tests/e2e` (browser and axe against a running stack; see its docstring).
